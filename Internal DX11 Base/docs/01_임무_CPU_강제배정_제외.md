# 01. 부하 주인공 — 임무 미지원 시 CPU 강제 배정 제외

## CT에서 확인된 동작

대상 항목은 `부하 주인공 — 임무 미지원 시 CPU 강제 배정 제외`이다.

- hook: `SAN8RPK.exe+1453801`
- 보조 검증 지점: `SAN8RPK.exe+1453790`
- manager root: `SAN8RPK.exe+2E98BC8`
- 원본 hook bytes: `49 8D 7F 20 BE 05 00 00 00`
- native resume: `SAN8RPK.exe+145380A`
- 강제 배정 처리 skip target: `SAN8RPK.exe+1453870`

CT 코드상 다음 조건을 모두 만족할 때 CPU의 해당 후보 처리 구간을 건너뛴다.

1. `[SAN8RPK.exe+2E98BC8]`가 유효하다.
2. `rbx == [managerRoot+0xE0]`이다.
3. `[rbx+0x10]`이 유효하다.
4. `byte ptr [[rbx+0x10]+0x8]`이 4 이상 9 이하이다.
5. `byte ptr [rbx+0x350] == 0`이다.

CT 주석의 의도는 **부하 상태의 플레이어가 임무 지원을 하지 않은 경우 CPU의 5개 임무 후보 목록에서 강제 배정되지 않게 하는 것**이며, 자원자 처리는 원래 게임 로직을 유지한다고 되어 있다.

## C++ 치트 적용안

### 상태/UI

- 단일 bool toggle로 구현한다.
- 내정/임무 관련 영역에 배치하는 것이 자연스럽다.
- 제안 기능명: `임무 미지원 시 CPU 강제 배정 제외`.

### hook 이식

구현 시 CT 코드를 그대로 무검증 JMP로 옮기지 않는다.

- `+1453801`의 9-byte 원본을 enable 전에 확인한다.
- CT가 별도로 assert하는 `+1453790 = 48 3B 98 E0 00 00 00`도 함께 확인한다.
- code cave에서 CT와 동일하게 flags와 `rax`를 보존한다.
- native 경로에서는 원본 명령 `lea rdi,[r15+20] / mov esi,5`를 실행한 뒤 `+145380A`로 복귀한다.
- 조건 만족 경로는 `+1453870`으로 이동한다.
- disable 시 현재 hook bytes가 우리 패치 상태일 때만 원본을 복구한다.
- 코드 메모리 쓰기 후 `FlushInstructionCache`를 사용한다.

현재 프로젝트의 `AIExecutionConditionChange.cpp`처럼 원본 바이트 배열, 현재 바이트 비교, 패치 소유권 확인, 원복 실패 처리 구조를 재사용하는 편이 안전하다.

## 현재 코드와의 중복 여부

확인한 현재 내정 UI 및 관련 모듈 범위에서는 이 CT와 동일한 임무 미지원/CPU 강제 배정 제외 기능을 확인하지 못했다. 따라서 **신규 기능 후보**로 분류한다.

단, 저장소 전체를 의미 기반으로 완전히 증명한 것은 아니므로 실제 구현 전에는 해당 offset과 주변 코드 참조를 다시 검색한다.

## 구현 전/후 확인 항목

- 게임 버전에서 두 assert 지점이 정확히 일치하는지 확인.
- 상태값 4..9 범위의 부하 주인공이며 `[+350] == 0`인 경우 CPU 강제 배정이 발생하지 않는지 확인.
- `[+350] != 0`일 때 원래 동작을 유지하는지 확인.
- 자원자 처리에 영향이 없는지 확인.
- toggle OFF 후 원본 임무 배정 동작이 복구되는지 확인.
- 다른 hook/외부 패치가 같은 구간을 점유했을 때 적용을 거부하는지 확인.

## 미확인 사항

- 상태값 4..9 각각의 게임 의미는 이 CT만으로 확정하지 않는다.
- `+0x350` 필드의 정식 구조체 명칭은 CT에서 제공하지 않는다.
- 실제 게임 런타임 검증은 이번 문서화 작업에서 수행하지 않았다.
