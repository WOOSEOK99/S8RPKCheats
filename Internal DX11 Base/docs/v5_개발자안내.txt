영토 단절 이동·배정·AI 차단 v5 — 개발자 전달 자료
작성: 2026-10-02 / Cheat Engine 7.2 x64 / Lua 5.3 / CT XML 34

1. 변경 목적과 호환 범위

기존 v4a는 VERSION.dll이 SAN8RPK.exe+17B0BA0에 설치한 후킹을
인식한 뒤 VERSION.dll 내부 트램펄린 포인터를 교체했다. VERSION의
호출 스택과 내부 주소에 의존하여 DLL 변경 시 재분석이 필요했다.

v5는 이 공용 함수 입구와 DLL 내부 메모리를 전혀 수정하지 않는다.
DLL MD5, DLL 로드 여부, DLL 내부 고정 주소도 사용하지 않는다.
동일 게임 빌드와 아래 게임 측 수정 지점이 유지되는 한, DLL에 다른
기능이 추가되거나 내부 주소가 이동해도 그 이유만으로 거부하지 않는다.

임의의 모든 변경과 항상 호환된다는 의미는 아니다. 다른 프로그램이
v5의 게임 측 지점/검사 영역을 수정하면 적용을 거부한다. 게임 빌드나
객체 구조 변경, DLL이 기존 이동 호출을 우회하는 경우에도 재검증한다.
기존 DLL 내장 영토 단절 기능 및 구버전 CT와 동시에 켜지 않는다.

2. DLL 내장판의 현재 실패 원인 (파일 분석 + 실제 메모리 확인)

조사 HID MD5: 1ab069a8856ead90ff8055672443c2a1
조사 VERSION MD5: 05861023e39184a5252dd41221c418c5
이 해시는 조사 파일 식별용이며 v5 실행 조건이 아니다.

HID+48520은 게임 측 열 곳의 원본 코드를 검사한다.
HID+4869F..486DD는 게임+17B0BA0의 14바이트를 원본
48 85 C9 0F 84 EA 12 00 00 44 88 4C 24 20과 비교한다.
VERSION이 이 입구를 후킹한 실제 실행에서 이 검사만 불일치했다.
HID+48D4A의 검사 실패는 아래 메시지를 남기고 설치 전에 반환한다.
  [영토단절] 적용 보류: CT 92011 원본 코드 상태 불일치
검사만 무시하면 HID+48EC5..48EE7이 VERSION의 입구 후킹을 덮는다.
따라서 검사 우회만으로 고치지 않는다.

3. 새 AI 호출 연결

구버전 공용 입구 필터는 원래 세 반환 주소만 선별했다.
  반환 주소        CALL 위치         원래 호출 대상
  +144A326         +144A321          +17B0BA0
  +144A8FA         +144A8F5          +17B0BA0
  +1450972         +145096D          +17B0BA0

v5는 이 세 CALL만 공통 검사 래퍼(cave+2400)로 연결한다.
RCX=무장, RDX=도착 도시, R8=이동에 전달되는 세력.
필터는 변경 없는 기존 helper(cave+874)를 사용한다.
허용: 레지스터/플래그/XMM0..5/스택을 복원하고 +17B0BA0으로 tail JMP.
차단: 동일하게 복원하고 바로 RET.
기존 DLL에는 원래 호출자의 반환 주소, shadow space, 5번째 이후
스택 인자가 그대로 전달된다. VERSION의 추가 스택 깊이를 추측하지 않는다.
원래 후킹 범위와 같이 일반 동일 세력 AI 전배만 제한한다. 세력 변경,
포로·등용·전쟁 점령에 관련된 이동을 공용 함수 전체에서 막지 않는다.

DLL 개발자가 직접 통합할 때에도 한 수정 지점은 한 구현만 소유한다.
이미 자체적으로 해당 CALL/함수를 수정한다면 별도 패치를 중첩하지 말고
그 처리 안에서 아래 판정 함수를 호출한다. 허용된 경우 기존 처리를 계속한다.
기능을 끌 때 다른 구현의 코드를 원본으로 강제 덮어쓰지 않는다.

4. 독립 판정 함수와 데이터

ConnectedCities(from, to) = cave+6B2, RCX/RDX 인자, EAX 0/1.
게임 객체의 유효성은 vtable+48 메서드를 통해 검사한다.
도시+20..+48의 6개 이웃 포인터를 순회한다.
도시+90 → 군단, 군단+10 → 세력. 유효하고 같은 세력인 이웃만 탐색한다.
출발/도착 도시의 세력이 같아야 하며 BFS 방문 한도는 256이다.
같은 유효 도시이면 연결로 본다. 실제 이동 자격은 원래 게임 검사가 맡는다.
이 함수는 도로 연결만 판단하며 무장/도시 데이터를 쓰지 않는다.

FilterAiSameForceTransfer(actor, target, force) = cave+874.
  무장/목표/현재 도시가 유효하고,
  force가 존재하며 actor+18의 세력과 같고,
  출발 도시와 목표 도시의 세력도 force와 같다면:
    return ConnectedCities(actor+20, target)
  그 외: return 1 (이 도로 제한의 적용 범위 밖; 원래 이동 처리에 맡김)

필터의 1은 모든 게임 자격을 충족했다는 의미가 아니다. 본 도로 제한을
통과했다는 의미이며 원래 신분/명령/인원 자격 검사를 생략해서는 안 된다.
게임이 처리 중인 유효 객체로 게임 스레드에서 호출한다. CE 작업 스레드에서
임의의 포인터를 넣어 executeCodeEx로 실행하지 않는다.

6. CE 적용/해제 수명

단일 체크로 설치한다. 모든 지점 검사 후 스레드를 잠시 정지하고 다시
검사한 뒤 설치한다. 중간 실패 시 시도한 쓰기를 역순 복구한다.
해제할 때는 자기 설치 바이트와 일치하는 경우에만 복구한다.
할당 메모리는 실행 중 복귀 주소 안전을 위해 게임 종료까지 유지한다.
PID+게임 베이스+프로세스 생성 시각으로 세션을 구분한다.
게임 재실행 후 이전 프로세스의 복원 기록을 새 게임에 쓰지 않는다.
다른 프로그램의 나중 변경을 무시하고 강제 복원하는 옵션은 제공하지 않는다.

진단 보고서 저장 (CE Lua 창에서):
  if SAN8RoadMovementV5 then SAN8RoadMovementV5.report() end

S=SAN8RoadMovementV5의 caves.movement가 코드 시작 주소이다.
entrypoints와 statsOffsets는 그 시작 주소에 대한 상대 위치이다.
ai_checked/ai_blocked는 새 AI CALL 래퍼에만 대한 누적 32비트 카운터다.
UI 또는 앞 단계 AI 후보 필터에서 이미 차단하면 이 카운터는 증가하지 않는다.
