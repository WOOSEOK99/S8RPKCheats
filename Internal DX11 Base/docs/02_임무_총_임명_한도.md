# 02. 임무 총 임명 한도 직접 입력 — 플레이어·CPU 공통

## CT에서 확인된 동작

대상 항목은 `임무 총 임명 한도 직접 입력 — 플레이어·CPU 공통 v0.3`이다.

실제 편집 값은 다음 전역 4-byte 데이터이다.

- 주소: `SAN8RPK.exe+3BB2148`
- CT 기본값: `10`
- 값 형식: 4 Bytes / decimal integer
- CT 주석: 플레이어와 CPU 도시에 공통 적용
- CT 주석: 값을 바꾼 뒤 임무 화면을 닫았다 다시 열어 반영 확인
- enable 시 값은 쓰지 않으며 현재값을 그대로 둔다.
- CT disable은 10으로 복구한다.

CT는 enable 시 아래 코드 참조가 예상 바이트인지 검증한다.

- `+685860 = 48 8D 05 A9 8D 52 03`
- `+1357341 = 44 8B B8 38 3B 00 00`
- `+1EA0883 = 3B A8 38 3B 00 00`
- `+1E9F0DA = 48 63 88 38 3B 00 00`
- `+1E9EBDE = 44 8B B8 38 3B 00 00`
- `+1E89E25 = 44 3B A0 38 3B 00 00`
- `+1452460 = 44 8B A0 38 3B 00 00`

## C++ 치트 적용안

이 기능은 hook보다 **전역 정수 값 편집 기능**으로 구현하는 것이 맞다.

### UI

- `임무 총 임명 한도` 정수 입력 필드.
- 현재 메모리 값을 읽어 표시한다.
- 사용자 편집 완료 시 4-byte 정수로 쓴다.
- CT에서 검증된 안전 범위는 기본값 10 외에는 없다. 임의로 최대값/최소값을 만들어 제한하지 말고 런타임 검증 결과가 생긴 뒤 범위를 정한다.

### 안전한 값 소유권

CT는 disable 시 무조건 10을 쓰지만 프로젝트 이식에서는 더 보수적으로 처리하는 편이 좋다.

1. 최초 적용 전에 현재값을 읽는다.
2. 예상 기본값 10 또는 우리가 이미 적용한 마지막 값인지 확인한다.
3. 최초 원본값을 캡처한다.
4. 변경할 때 현재값이 마지막 적용값과 다르면 외부 변경으로 보고 덮어쓰지 않는다.
5. 해제 시 현재값이 우리 마지막 적용값일 때만 캡처한 원본값으로 복구한다.

이 방식은 현재 `ShortBattleCooldown.cpp`의 가변 전역값 처리 패턴과 같은 방향이다.

### 버전 검증

단순 데이터 주소라고 해서 `+3BB2148`만 믿지 않는다. CT에 있는 7개 코드 참조 assert를 가능한 범위에서 검증해야 한다. 최소한 값 주소와 주요 참조 명령의 일치 여부를 확인하고, 실패 시 기능을 비활성화한다.

## 현재 코드와의 중복 여부

확인한 현재 내정 UI 및 관련 모듈 범위에서는 임무 총 임명 한도를 직접 조절하는 기능을 확인하지 못했다. **신규 기능 후보이며 4개 기능 중 구현 난도가 가장 낮아 우선 적용하기 좋다.**

## 구현 전/후 확인 항목

- 기본 상태에서 `+3BB2148` 값이 10인지 확인.
- 값을 변경했을 때 플레이어 임무 화면에서 총 임명 가능 수가 바뀌는지 확인.
- CPU 도시에도 동일 한도가 적용되는지 별도 확인.
- 화면을 닫고 다시 열었을 때 변경값이 반영되는지 확인.
- 비정상적으로 큰 값/음수/0의 동작은 안전하다고 가정하지 말고 별도 테스트.
- 외부 도구가 값을 변경한 상태에서 우리 기능이 그 값을 덮어쓰지 않는지 확인.
- 해제 시 최초 원본값이 정확히 복구되는지 확인.

## 미확인 사항

- 10 이외 값의 유효 범위 및 게임 내부 최대 안전값은 CT에서 제공하지 않는다.
- 각 assert 지점이 정확히 어떤 서브시스템에서 한도를 소비하는지는 이 문서에서 역어셈블까지 확정하지 않았다.
- 실제 게임 런타임 검증은 이번 문서화 작업에서 수행하지 않았다.
