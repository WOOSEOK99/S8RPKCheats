# 03. 내정 포상 조건 완화

## CT에서 확인된 구성

CT에는 같은 hook을 사용하는 두 가지 **택일** 항목이 있다.

1. `내정 포상 — 실적 200% 이상, 3위 이내 포상`
2. `내정 포상 — 실적 200% 이상, 등수 무관 포상`

두 항목 모두 다음 위치를 패치한다.

- hook: `SAN8RPK.exe+1C813D1`
- 원본 bytes: `48 89 74 24 30`
- native resume: `SAN8RPK.exe+1C813D6`

따라서 두 기능을 서로 독립적인 체크박스로 구현하면 안 된다. 동시에 활성화될 경우 같은 5 bytes의 소유권이 충돌한다.

## 공통 조건

두 CT 스크립트는 code cave에서 다음 조건을 검사한다.

1. `r13 != 0`
2. `r13 != [rbp-0x48]`
3. `[r13+0x20] == [rbp-0x68]`
4. `byte ptr [r13+0xF8] != 0`
5. `dword ptr [r13+0x348] >= 200`

조건이 맞으면 대상 수령자를 `rsi = r13`으로 대체하고, 마지막에는 원본 명령 `mov [rsp+30],rsi`를 실행한다.

CT 주석은 실제 순위/실적 임계값, 원래의 금액 및 대화 조건을 유지하고 **수령 플레이어만 대체하며 플레이어 태수는 대체하지 않는다**고 설명한다.

## 모드별 차이

### 200% 이상 + 3위 이내

공통 조건에 더해 다음 순위 조건이 있다.

```text
mov eax,[r13+34C]
dec eax
cmp eax,2
ja native
```

CT 설명 기준으로 3위 이내를 허용하는 모드다.

### 200% 이상 + 등수 무관

`[r13+0x34C]` 순위 검사를 하지 않는다. 공통 조건과 실적 200% 이상 조건이 맞으면 수령자를 대체한다.

## C++ 치트 적용안

### UI/상태

bool 2개가 아니라 하나의 모드 값으로 구현한다.

```text
Off
Achievement200Top3
Achievement200AnyRank
```

UI는 radio/combo 형태가 적합하다.

### hook

- 하나의 hook만 `+1C813D1`에 설치한다.
- cave 내부에서 현재 선택 모드를 읽어 Top3일 때만 순위 검사를 수행한다.
- enable 전에 원본 5 bytes가 정확히 일치하는지 확인한다.
- disable 시 현재 hook이 우리 패치인지 확인한 뒤 원본 5 bytes를 복구한다.
- 코드 메모리 쓰기 후 instruction cache를 flush한다.
- hook/cave 상태 관리는 현재 프로젝트의 robust hook 소유권 패턴을 따른다.

CT는 `계절 실적 결과 창이 열린 동안 enable`하라는 사용 메모가 있다. C++ 이식에서 항상 켜두어도 안전한지는 CT만으로 확정할 수 없으므로, 구현 후 화면 진입/이탈 시점까지 런타임 검증한다.

## 현재 코드와의 중복 여부

확인한 현재 내정 UI 및 관련 모듈 범위에서는 동일한 내정 포상 수령 조건 완화 기능을 확인하지 못했다. **신규 기능 후보**로 분류한다.

## 구현 전/후 확인 항목

### Top3 모드

- 실적 200% 이상 + 1~3위 대상이 포상을 받는지 확인.
- 200% 이상이어도 4위 이하가 원래 로직을 유지하는지 확인.
- 200% 미만이 원래 로직을 유지하는지 확인.

### 등수 무관 모드

- 실적 200% 이상이면 순위와 무관하게 의도한 수령자 대체가 발생하는지 확인.
- 200% 미만은 원래 로직을 유지하는지 확인.

### 공통

- 플레이어 태수를 잘못 대체하지 않는지 확인.
- 포상 금액과 대화 조건이 원래 로직을 유지하는지 확인.
- 모드 전환 시 hook 중복 설치가 없는지 확인.
- Off 전환 시 원본 bytes가 복구되는지 확인.
- 외부 패치가 같은 5-byte 구간을 변경했으면 덮어쓰지 않는지 확인.

## 미확인 사항

- `r13+0x20`, `+0xF8`, `+0x348`, `+0x34C`의 정식 구조체 필드명은 CT만으로 확정하지 않는다.
- 순위 필드의 내부 표현은 CT 설명과 코드 동작에 맞춰 사용하되, 실제 게임 데이터에서 별도 확인한다.
- 실제 게임 런타임 검증은 이번 문서화 작업에서 수행하지 않았다.
