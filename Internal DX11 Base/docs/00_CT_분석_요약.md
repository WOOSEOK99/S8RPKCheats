## 적용 순서 제안

1. **임무 총 임명 한도**
   - 코드 케이브가 필요 없고 `SAN8RPK.exe+3BB2148`의 4-byte 값만 다룬다.
   - CT 기본값은 10이다.
   - 임의의 안전 범위는 CT에서 확인되지 않으므로 구현 단계에서 근거 없이 clamp 값을 만들지 않는다.

2. **내정 포상 조건 완화**
   - `끔 / 200% 이상 + 3위 이내 / 200% 이상 + 등수 무관`의 단일 모드로 구현한다.
   - 두 모드는 `SAN8RPK.exe+1C813D1`의 동일 5 bytes를 점유하므로 하나의 hook 안에서 분기해야 한다.

3. **부하 주인공 CPU 강제 배정 제외**
   - `SAN8RPK.exe+1453801` 코드 케이브 hook이다.
   - 원본 바이트 검증, hook 소유권 확인, 안전한 원복을 포함해서 이식한다.

4. **기술도시 게임 내 편집기 표시**
   - `SAN8RPK.exe+12CA4F5`의 `74 50`을 `90 90`으로 바꾸는 작은 패치다.
   - CT 작성 메모에는 2026-09-30 실행 코드 검증이라고 적혀 있으나, UI 선택/저장/재로드는 아직 게임 내 테스트되지 않았다고 명시되어 있다.

## 프로젝트 적용 공통 원칙

- 모든 `SAN8RPK.exe+offset`은 게임 버전에 종속되므로 CT의 `assert` 바이트를 버리지 않는다.
- enable 전에 원본/예상 바이트를 확인하고, 예상 상태가 아니면 적용을 거부한다.
- disable 시 현재 바이트/값이 이 기능이 마지막으로 적용한 상태인지 확인한 뒤 원복한다. 다른 도구의 변경을 덮어쓰지 않는다.
- code cave 기능은 현재 프로젝트의 robust hook 구현에서 사용하는 원본 바이트 검증/패치 소유권/Instruction Cache flush 방식을 따른다.
- 직접 값 편집 기능은 현재 프로젝트의 가변 전역값 기능처럼 최초 원본값을 캡처하고 외부 변경을 감지하는 방식을 따른다.
- UI/설정 추가는 실제 기능 구현 시에만 수행한다. 이번 문서 작업에서는 기존 코드나 설정 파일을 수정하지 않는다.
