# Step 01 - 현재 AI 전투 개선과 SAN8RPK_Viewer 비교

## 1. S8RPKCheats 현재 구현 - 확정

기준 파일:

- `Internal DX11 Base/Cheats/War/Roadblock.cpp`
- 기준 blob SHA: `c0d800123b29812091bf5b66944ae1d151be62a9`

현재 `AI 전투 개선`은 code cave가 아니라 **3개의 직접 바이트 패치**를 하나의 토글로 묶은 구조입니다.

| 기능명(현재 소스 주석) | RVA | 원본 | 적용 |
|---|---:|---|---|
| 복수 공격 분기 | `+0x144D24C` | `74 0A` | `EB 0A` |
| 주인공 대상 호전성 증가 분기 제거 | `+0x1464B91` | `75 1E` | `90 90` |
| 일부 군주의 공백지 점령 제한 플래그 무력화 | `+0x145BDAB` | `B8 01 00 00 00` | `B8 00 00 00 00` |

현재 구현은 세 주소를 먼저 모두 검증하고, 하나라도 원본/적용 바이트와 다르면 전체 적용을 중지합니다. 쓰기 중 실패하면 이번 호출에서 변경한 주소를 원래 상태로 되돌립니다.

UI 설명은 다음 세 효과를 묶어 설명합니다.

- 한 세력이 한 턴에 여러 세력을 공격 가능
- 주인공만 지나치게 공격하는 행동 완화
- 일부 군주의 빈 도시 점령 제한 완화

## 2. Viewer의 공격 로직 - 1차 확정

`ai_profile`에서 메인 공격 관련 hook RVA로 다음 값이 직접 추출됩니다.

- `HOOK_RVA = +0x144D248`

해당 지점에 대응하는 원본 바이트 상수:

```text
49 3B 4D 30 74 0A 48 8B 47 18 49 3B 45 38 75 22
```

여기서 매우 중요한 중복이 있습니다.

```text
Viewer hook start    +144D248 : 49 3B 4D 30
S8RPKCheats patch    +144D24C : 74 0A -> EB 0A
```

즉 **우리의 첫 번째 '복수 공격' 패치는 Viewer가 통째로 code cave hook을 거는 블록 내부의 정확히 +4 위치에 존재**합니다.

이 사실은 두 구현이 완전히 별개의 기능이 아니라 **같은 AI 전쟁 판단 코드 경로를 서로 다른 방식으로 수정하고 있다는 강한 증거**입니다.

## 3. 가장 큰 차이

### S8RPKCheats

현재 구현은 해당 조건분기 `74 0A`를 `EB 0A`로 바꿔서 조건을 강제로 우회합니다.

장점:

- 매우 작고 단순함.
- 원복이 쉬움.
- 실행 비용이 사실상 없음.

한계:

- 분기의 의미를 세밀하게 재계산하지 않음.
- 해당 조건을 항상 같은 방향으로 우회함.

### SAN8RPK_Viewer

Viewer는 `+144D248`부터 더 큰 블록을 hook한 뒤 **code cave의 별도 판단 로직**을 실행합니다.

`ai_profile`에는 공격 payload에서 사용하는 것으로 보이는 다음 문자열/개념이 존재합니다.

- `stats`
- `relation`
- `score`
- 별도 helper 함수 RVA들
- cave 내부 카운터 증가 코드

따라서 Viewer는 단순히 `74 -> EB` 한 줄만 바꾸는 수준이 아니라, 같은 지점을 진입점으로 삼아 **후보/관계/점수 계열 판단을 추가하는 확장 구현**으로 보입니다.

정확한 점수식과 후보 필터는 Step 03에서 payload를 명령어 단위로 해부해야 확정할 수 있습니다.

## 4. Viewer에 존재하는 추가 static patch - 확정

`ai_profile`에서 다음 두 static patch가 직접 확인됩니다.

### +0x144BB60

원본:

```text
48 B8 00 88 9F 2A 03 00 00 00 48 03 F0
```

적용:

```text
90 90 90 90 90 90 90 90 90 90 90 90 90
```

### +0x144BC8B

원본:

```text
48 81 C6 00 F1 53 65
```

적용:

```text
90 90 90 90 90 90 90
```

이 두 NOP 패치의 **정확한 게임 의미는 아직 미확정**입니다. 주변 게임 원본 디스어셈블리와 공격 후보 자료구조를 연결한 뒤 이름을 붙여야 합니다.

## 5. 현재 우리 패치 2/3과 Viewer의 관계

우리 소스가 직접 수정하는:

- `+0x1464B91`
- `+0x145BDAB`

두 RVA는 현재 추출한 `ai_profile`의 Python 정수 상수 목록에는 나타나지 않았습니다.

따라서 현재 단계에서 확인 가능한 사실은:

- Viewer는 **우리와 동일한 +1464B91 직접 NOP 패치 방식을 사용하지 않음**.
- Viewer는 **우리와 동일한 +145BDAB immediate 값 변경 방식을 사용하지 않음**.
- 플레이어 우선공격 제거가 Viewer 설명대로 구현되어 있다면, 그 처리는 메인 공격 code cave 또는 다른 hook 내부에서 이루어질 가능성이 높음.
- 우리 쪽의 공백지 제한 해제는 Viewer에 동일 주소 패치가 없으므로 **우리 쪽에만 있는 별도 보완일 가능성**이 있음. 단, Viewer code cave가 같은 효과를 다른 방식으로 만들 가능성은 아직 배제할 수 없음.

## 6. 현재 결론

두 기능은 이름과 목적이 비슷하지만 구현 범위는 같지 않습니다.

### 겹치는 부분

- 같은 AI 전쟁 판단 경로를 수정.
- 특히 `+144D24C`는 Viewer 메인 hook `+144D248` 내부에 정확히 포함됨.
- 따라서 두 패치를 동시에 적용하면 충돌 가능성이 매우 높음.

### 현재 S8RPKCheats에만 직접 확인되는 부분

- `+1464B91 : 75 1E -> 90 90`
- `+145BDAB : B8 01 -> B8 00`

### Viewer 쪽이 더 큰 부분

- `+144D248` code cave hook
- 후보/관계/점수로 보이는 추가 계산
- `+144BB60`, `+144BC8B` static NOP patch
- 공격 이외에도 포로/처형/항복권고 로직이 같은 AI 프로필 안에 포함됨

## 7. 이식 시 주의

Viewer의 공격 기능을 나중에 S8RPKCheats로 옮길 경우:

1. 기존 `+144D24C` 패치를 그대로 둔 채 Viewer의 `+144D248` hook을 추가하면 안 됨.
2. 먼저 Viewer payload가 기존 `74 0A` 분기를 어떤 조건으로 대체하는지 완전히 해부해야 함.
3. 이후 기존 3개 패치 중 유지할 것과 Viewer 방식으로 대체할 것을 각각 결정해야 함.
4. 플레이어 우선공격 제거와 공백지 점령은 별도 A/B 테스트 항목으로 분리해야 함.

현재 단계에서는 **기존 AI 전투 개선을 삭제하거나 변경하지 않습니다.**
