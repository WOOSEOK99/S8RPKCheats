# Step 06 - AI 처형 로그 상세화

## 0. 범위

이 문서는 `SAN8RPK_Viewer.exe`의 독립 메시지 기능을 분석합니다.

Viewer UI의 표현:

```text
포로 결과 메시지 켜기
메시지 확장 켜짐 · AI 전투의 등용·석방 결과 + 복수 처형 명단 표시
```

이번 기능은 Step 05의 **AI가 누구를 처형할지 결정하는 로직**과 별개입니다.

---

## 1. 내부 프로필의 명시적 설명 - 확정

`message_profile.py`의 module docstring:

```text
Exact-build, display-only branches. No code cave or decision changes.
```

`message_patch.py`의 module docstring:

```text
Independent, reversible in-game captive-result message switch.
```

따라서 제작자가 코드 자체에 명시한 설계는:

- 특정 게임 빌드 전용
- 표시 분기만 변경
- code cave 없음
- AI 의사결정 변경 없음
- 독립적으로 켜고 끌 수 있음
- 원복 가능

입니다.

이 부분은 **확정**입니다.

---

## 2. Viewer UI가 설명하는 실제 범위 - 확정

Viewer에는 다음 문자열이 직접 존재합니다.

### 꺼짐

```text
메시지 확장 꺼짐 · AI 전투의 등용·석방 결과 및 복수 처형 명단 표시
```

### 켜짐

```text
메시지 확장 켜짐 · AI 전투의 등용·석방 결과 + 복수 처형 명단 표시
```

따라서 이 기능은 단순히 “처형자 이름만 더 표시”하는 한 가지 패치가 아니라 최소 두 범주를 포함합니다.

1. **AI 전투의 등용·석방 결과 표시**
2. **여러 명이 처형됐을 때 상세 명단 표시**

---

## 3. 전체 hook 목록 - 확정

`message_profile.HOOKS` 최종 구성은 4개입니다.

| 내부 offset key | RVA | 원본 |
|---:|---:|---|
| 0 | `+0x01E5BA1F` | `0F 84 D1 00 00 00` |
| 1 | `+0x01E599BE` | `74 75` |
| 2 | `+0x01E5A82C` | `75 59` |
| 3 | `+0x01E5BA4B` | `BA 43 00 00 00` |

최종 `replacement(offset)` 함수는 각 위치를 다음처럼 바꿉니다.

| key | replacement |
|---:|---|
| 0 | `41 0F B6 C6 90 90` |
| 1 | 원본 길이만큼 NOP → `90 90` |
| 2 | 원본 길이만큼 NOP → `90 90` |
| 3 | `8D 54 80 3E 90` |

즉 네 군데 모두 **원본과 정확히 같은 길이**로 치환합니다.

trampoline이나 원격 cave는 없습니다.

---

## 4. Patch 1 - +1E599BE - 확정 바이트 / 역할 유력

### 원본

```text
74 75
```

x86-64:

```asm
je +0x75
```

### 변경

```text
90 90
```

즉 조건이 참일 때 멀리 건너뛰던 분기를 제거하고 **항상 바로 다음 코드로 fall-through**하게 만듭니다.

원래 branch target:

```text
+1E599BE + 2 + 0x75
= +1E59A35
```

### 의미

이 주소는 독립 guard 영역 `+1E599BB` 안에 있고, Viewer UI는 AI 전투의 **등용·석방 결과**를 추가 표시한다고 설명합니다.

따라서 이 branch는 AI-only 전투에서 결과 메시지를 생략하던 조건 중 하나로 보는 것이 강합니다.

다만 현재 확보한 원본 게임 함수 전체가 없기 때문에:

- 이것이 정확히 “등용”인지
- 또는 정확히 “석방”인지

는 아직 **미확정**입니다.

주소 순서와 UI 설명 순서를 기준으로 `+1E599BE = 등용`일 가능성이 높지만 문서에서는 **유력**으로만 둡니다.

---

## 5. Patch 2 - +1E5A82C - 확정 바이트 / 역할 유력

### 원본

```text
75 59
```

x86-64:

```asm
jne +0x59
```

### 변경

```text
90 90
```

이 역시 조건분기를 제거하고 **항상 fall-through**하도록 만듭니다.

원래 branch target:

```text
+1E5A82C + 2 + 0x59
= +1E5A887
```

### 의미

Patch 1과 동일하게 별도 메시지 표시 조건을 우회하는 패치입니다.

Viewer UI 범위가 “등용·석방 결과”이므로 두 2-byte NOP 패치를 각각 이 두 결과 표시와 연결하는 것이 자연스럽습니다.

현재 가장 유력한 매핑:

```text
+1E599BE -> AI 등용 결과 표시
+1E5A82C -> AI 석방 결과 표시
```

하지만 게임 원본 함수 전체 디스어셈블리가 없으므로 **1:1 매핑은 아직 확정하지 않습니다.**

중요한 사실은 두 패치 모두 **결과 판정 자체를 바꾸지 않고 표시 경로를 생략하는 조건만 제거**한다는 점입니다.

## 6. 복수 처형 상세화는 두 패치가 한 세트 - 확정

나머지 두 RVA:

```text
+1E5BA1F
+1E5BA4B
```

는 동일 guard 영역:

```text
+1E5BA17, size 235
```

안에 함께 존재합니다.

따라서 하나의 함수 내부에서 함께 작동하는 패치입니다.

---

## 7. Patch 0 - +1E5BA1F

### 원본

```text
0F 84 D1 00 00 00
```

해석:

```asm
je +0xD1
```

branch target:

```text
+1E5BA1F + 6 + 0xD1
= +1E5BAF6
```

### 변경

```text
41 0F B6 C6 90 90
```

해석:

```asm
movzx eax, r14b
nop
nop
```

즉 원래의 조건부 점프를 없애면서 동시에:

```text
EAX = zero_extend(R14B)
```

를 수행합니다.

이것은 단순 NOP가 아니라 **후속 코드에 r14의 하위 8-bit 값을 명시적으로 전달**하는 변경입니다.

---

## 8. Patch 3 - +1E5BA4B

### 원본

```text
BA 43 00 00 00
```

해석:

```asm
mov edx, 0x43
```

즉:

```text
EDX = 67
```

이라는 고정값입니다.

### 변경

```text
8D 54 80 3E 90
```

해석:

```asm
lea edx, [rax + rax*4 + 0x3E]
nop
```

따라서:

```text
EDX = 5 * EAX + 62
```

로 바뀝니다.

Patch 0과 합치면:

```text
EAX = R14B
EDX = 5 * R14B + 62
```

입니다.

---

## 9. 왜 이것이 “복수 처형 명단”과 연결되는가

여기서 확인되는 구조는 매우 특징적입니다.

### 바닐라

```text
EDX = 67
```

즉 항상 하나의 고정 ID/인덱스를 사용합니다.

### Viewer

```text
EAX = R14B
EDX = 62 + 5*EAX
```

즉 어떤 작은 정수값에 따라 **5씩 간격을 둔 여러 항목 중 하나를 동적으로 선택**합니다.

예:

| EAX | EDX |
|---:|---:|
| 0 | 62 |
| 1 | 67 |
| 2 | 72 |
| 3 | 77 |
| 4 | 82 |

특히:

```text
EAX = 1일 때 EDX = 67
```

이므로 바닐라의 고정값 `67`과 정확히 일치합니다.

이 구조는:

> 1명일 때는 원래 메시지와 같은 템플릿을 쓰고, 인원수/항목수가 늘어날수록 다른 메시지 템플릿을 선택한다

는 설계와 매우 잘 맞습니다.

Viewer UI가 이 패치 범위를 **“복수 처형 명단 표시”**라고 직접 설명하기 때문에, `R14B`가 처형 결과 수 또는 그에 대응되는 메시지 선택 인덱스일 가능성이 매우 높습니다.

다만 원본 게임 함수 전체가 없으므로:

```text
R14B == 정확한 처형 인원수
```

라고까지는 아직 확정하지 않습니다.

현재 분류:

- `R14B` = 복수 처형 메시지 선택에 사용되는 카운트/인덱스: **유력**
- 정확히 실제 처형자 수와 1:1인가: **미확정**

## 10. 게시글 설명과의 대응

사용자 제공 설명:

> AI끼리 전투나서 누가 처단되었을때 XX외 2명이 처형되었습니다 이렇게만 나오면  
> 도대체 나머지는 누가 처형된건지 알길이 없었습니다.

그리고:

> 플레이어 세력이 관여한 전쟁에서는 누가 처형되었는지 나오기 때문에 그로직을 그대로 가져왔습니다.

정적 코드에서 확인되는 사실:

1. 처형 메시지 함수의 기존 조건부 branch를 제거
2. 기존 고정 메시지 선택값 `67`을 동적 선택식으로 변경
3. 동적 선택식은 앞에서 가져온 8-bit 값에 따라 5 단위로 이동
4. Viewer 자체 UI가 이 기능을 “복수 처형 명단 표시”라고 설명

따라서 게시글의 설명과 실제 패치는 매우 잘 일치합니다.

다만 **“플레이어 전투용 로직을 그대로 가져왔다”**는 구현 출처까지는 현재 코드만으로 직접 증명하지 못했습니다. 해당 주장은 게시글 설명에 기반한 정보로 따로 구분합니다.

## 11. 이 기능은 AI 판단에 영향을 주지 않는다 - 확정

가장 중요한 부분입니다.

`message_profile` 자체가:

```text
No code cave or decision changes.
```

라고 명시합니다.

실제 네 패치도:

- 두 개는 조건 branch NOP
- 하나는 메시지용으로 보이는 레지스터 값 전달
- 하나는 고정 ID를 동적 ID 공식으로 변경

뿐입니다.

Step 05의 포로 판정 hook:

```text
+1E52A8D
+1E54190
```

와도 주소가 완전히 다릅니다.

따라서:

- 누가 석방되는가
- 누가 처형되는가
- AI의 처형 확률

을 바꾸는 기능이 아니라 **이미 결정된 결과를 어떤 메시지로 보여줄지 바꾸는 기능**으로 분류할 수 있습니다.

## 14. S8RPKCheats 현재 소스와 충돌 여부

현재 S8RPKCheats의 최신 소스에서 이 네 RVA를 직접 사용하는 기능은 확인되지 않았습니다.

```text
+1E5A82C
+1E5BA1F
+1E5BA4B
```

기존 `도독 포로 직접 처분`은 다른 주소를 사용하며, 기능 목적도 플레이어 도독의 포로 처분 선택권입니다.

따라서 현재 확인 범위에서는 **직접 주소 충돌 없음**입니다.

## 15. 이식 난이도

이 기능은 지금까지 분석한 Viewer 기능 중 상당히 이식하기 쉬운 편입니다.

이유:

- code cave 없음
- 동적 메모리 할당 없음
- 외부 helper 호출 없음
- 네 군데 fixed-length patch
- 원본 바이트가 모두 명확
- 해제 시 원본 바이트 그대로 복구 가능
- AI 판단 로직과 독립

단, 실제 이식 전에 반드시 게임에서 다음을 A/B 검증해야 합니다.

1. AI vs AI 전투에서 포로 등용 발생
2. AI vs AI 전투에서 포로 석방 발생
3. AI vs AI 전투에서 1명 처형
4. AI vs AI 전투에서 2명 이상 동시 처형
5. 플레이어 참여 전투 메시지가 바뀌거나 깨지지 않는지

```text
+1E599BE only
```

### B

```text
+1E5A82C only
```

### C

```text
+1E5BA1F + +1E5BA4B
```

이렇게 하면 등용/석방 두 주소의 의미도 게임에서 바로 확정할 수 있습니다.

## 17. Step 06 결론

### 확정

Viewer의 메시지 확장은 정확히 4개 fixed-size patch입니다.

```text
+1E599BE : 74 75 -> 90 90
+1E5A82C : 75 59 -> 90 90
+1E5BA1F : 0F 84 D1 00 00 00
             -> 41 0F B6 C6 90 90
+1E5BA4B : BA 43 00 00 00
             -> 8D 54 80 3E 90
```

이 기능은:

- code cave 없음
- AI 의사결정 변경 없음
- 독립 토글
- 완전 원복 가능

입니다.

### 유력

- 앞의 두 branch NOP는 AI 전투의 **등용/석방 결과 표시 제한 해제**.
- 뒤의 두 패치는 **복수 처형 상세 명단을 위한 메시지 템플릿 선택 확장**.
- `R14B`는 복수 처형 결과의 수/인덱스와 관련된 값.

### 미확정

- `+1E599BE`와 `+1E5A82C` 중 정확히 어느 것이 등용이고 어느 것이 석방인지.
- `R14B`가 정확히 처형 인원수 자체인지.
- `EDX = 62 + 5*n`이 실제 어떤 메시지 테이블 ID 체계인지.

이 세 가지는 실제 게임 A/B 테스트로 쉽게 확정할 수 있습니다.
